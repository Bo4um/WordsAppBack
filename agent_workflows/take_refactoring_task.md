# Описание
Этот воркфлоу заставляет агента взять одну свободную задачу из плана рефакторинга, СНАЧАЛА ЗАБЛОКИРОВАТЬ ЕЁ для других, выполнить в изолированной ветке, проверить тестами и задокументировать результат.

# Инструкция для агента
Ты — Автономный ИИ-разработчик (Java/Spring Boot). Выполни следующие шаги в строгой последовательности, используя доступ к файловой системе и встроенный терминал:

1. ПОИСК И ЗАХВАТ ЗАДАЧИ (КРИТИЧЕСКИЙ ШАГ):
- Прочитай файл `parallel_refactoring_plan.md` в корне проекта.
- Найди первую сверху задачу со статусом `[ ] Статус: Не начато`.
- Если все задачи имеют статус `[x] Готово` или `[⏳] В работе`, выведи сообщение "Нет доступных задач для выполнения" и останови работу.
- КАК ТОЛЬКО НАШЕЛ ЗАДАЧУ: Прежде чем создавать ветку или писать код, открой файл `parallel_refactoring_plan.md` и **СРАЗУ ЖЕ** измени её статус на `[⏳] Статус: В работе`. Сохрани файл! Это необходимо, чтобы другие параллельные агенты не взяли эту же задачу.

2. ПОДГОТОВКА ОКРУЖЕНИЯ:
- Используя терминал, создай новую ветку на основе названия задачи (формат: `git checkout -b refactor/имя-задачи`).

3. ВЫПОЛНЕНИЕ РЕФАКТОРИНГА:
- Изучи цель и критерии приемки выбранной задачи.
- Внеси изменения в код. **КРИТИЧЕСКОЕ ПРАВИЛО:** Изменяй ТОЛЬКО файлы и директории, указанные в поле "Разрешенные файлы/директории".
- Соблюдай стандарты слоистой архитектуры Spring Boot.

4. ПРОВЕРКА КОДА (ТЕСТЫ И СБОРКА):
- Открой терминал и запусти сборку проекта с тестами (используй `mvn clean test` или `./gradlew test` в зависимости от того, что используется в проекте).
- Если сборка упала или тесты не прошли, проанализируй вывод терминала, исправь свои ошибки в коде и запусти тесты заново. Не переходи к следующему шагу, пока сборка не станет успешной.

5. ОТЧЕТНОСТЬ И ОБНОВЛЕНИЕ ПЛАНА:
- Снова открой `parallel_refactoring_plan.md` и обнови блок твоей задачи:
  - Измени статус с `[⏳] Статус: В работе` на `[x] Готово`.
  - Заполни "Что было изменено" (конкретные классы/методы).
  - Заполни "Зачем это было сделано" (архитектурное обоснование).
  - Укажи использованные Git-команды.

6. ФИКСАЦИЯ ИЗМЕНЕНИЙ:
- Используя терминал, выполни команды для сохранения работы:
  `git add .`
  `git commit -m "Refactor: [название задачи] - [суть изменений]"`
  `git push origin [название ветки]`
